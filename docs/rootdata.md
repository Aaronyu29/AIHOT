# 融资项目观察与 RootData

本站从现有公开新闻发现融资线索，以 RootData Basic 补充项目基础档案，由模型自动筛选值得跟踪的项目并公开展示。读者从 `/funding` 进入项目列表和详情；后台 `/admin/funding` 查看最近自动审核的结论、理由、时间和模型，无需逐项人工批准。

## 数据边界

- 融资证据来自本站已收录且当前允许公开的新闻，展示摘要、原文链接与报道时间。报道时间不冒充融资交割日期。
- RootData 提供项目名称、介绍、标签、运营状态以及官网和 RootData 链接。缺失字段保持未知。
- Basic 不支持融资轮次、投资方、榜单或变更通知。本站不调用 `get_fac`、`ser_change` 或其他付费套餐接口，也不把累计融资额当成本轮融资。
- 项目名称有歧义或证据不足时保留为候选，等待新资料后自动重评；模型认定不符合跟踪条件的项目不公开。跟踪结论不代表项目质量或投资回报。
- 后台保留可选的手动调整。修改入选状态或理由本身不触发重评，之后基础档案或新闻证据变化会重新审核；手动暂停不会被自动审核恢复，需手动恢复跟踪。
- 后续新闻通过公开内容读取层关联；撤回的报道不继续作为公开证据。RootData 的档案刷新不改变融资报道的时间。
- 本业务线覆盖本站新闻源发现的项目，不是全网完整融资数据库。

接口依据：[RootData API 文档](https://cn.rootdata.com/api/doc)，核对日期 2026-10-22；Basic 套餐额度以实际 `quotacredits` 返回和账号套餐为准。

## 配置与启动

后端环境变量（或 `AIHOT_CREDENTIALS_DIR` 下的 collectors 凭据文件）：

```dotenv
ROOTDATA_ENABLED=false
ROOTDATA_API_KEY=
ROOTDATA_MONTHLY_CREDITS=800
ROOTDATA_DAILY_CREDITS=24
```

密钥只放在部署的运行环境，不提交 Git，也不传给 web 容器。配置 key 并明确设为 `ROOTDATA_ENABLED=true` 后，worker 才允许外部查询；还需 `COLLECT_ENABLED=true`。没有密钥时仍可检查现有新闻线索与页面空状态。

模块已经登记在 `site/modules/`，Docker 镜像包含模块包。升级执行正常数据库迁移，然后重新构建并启动 api、worker、web。新增数据保存在模块自己的表里，不改写既有新闻、模型预算或其他数据源配置。

搜索与额度查询不扣 credits，但仍受请求频率保护；项目详情每次 2 credits。请求经过回执与预算检查，详情按七天缓存，默认本模块每日最多 24、滚动 31 天最多 800 credits，并为账号保留至少 100 credits。余额未知或不足时暂停资料刷新，保留已经保存的资料；前台读取不调用 RootData。

## 自动筛选、项目分析和持续更新

自动审核和分析复用网站现有模型及预算配置，都默认使用 `LLM_MODEL`，本部署为 DeepSeek Flash。审核可单独设置 `ROOTDATA_REVIEW_MODEL`，分析可单独设置 `ROOTDATA_ANALYSIS_MODEL`，也可在后台“模型与评测”调整；二者独立配置，不互相继承单独覆盖值。不需要新增 LLM key。`MODEL_CALLS_ENABLED=true` 时才允许模型调用。

每 15 分钟检查新闻线索和档案刷新；自动审核在每小时第 2、17、32、47 分钟运行，每轮最多调用 6 次。模型根据现有公开证据判断值得跟踪、等待更多资料或暂不跟踪；符合条件的项目自动公开，证据不足则继续保留为候选。新报道或基础档案变化后自动重评，暂停项目不自动恢复。已排除项目仍接收新报道以便重评，但不会持续消耗 RootData 档案额度；重评回到候选或入选后恢复档案刷新。资料未变且已有审核结论时跳过调用；失败至少间隔一小时再尝试，结果不明的请求不直接重发。

分析在每小时第 7、22、37、52 分钟运行，每次最多处理 3 个已入选、待分析的项目。相同资料重复访问或同步不会重跑模型；资料变化后缓存失效，后台重新分析。分析失败至少间隔一小时重试。公开证据被撤回或修订后，旧分析立即隐藏。后台展示的是最近一次自动审核记录，任务完成前不会把它标作新资料的审核结论。

分析涵盖产品与用户、明确披露的部署链、公开宣发、条件性前景、机会与风险、下一步核验事项。每项区分来源披露、模型判断、信息未确认，引用必须能在输入摘要或档案中逐字核验。缺少链上和社交数据时保持未知；引用校验不能替代人工研究，也不保证模型判断正确。融资和代币销售平台不会自动证明部署链或投资回报。

## 验收

1. 运行类型检查、模块的独立测试和数据库测试、网站构建与页面测试、迁移安全检查。
2. 配置后先确认后台显示 Basic 与剩余额度，错误记录中不含 key。
3. 用真实新闻核对项目名称和原文，确认 RootData 匹配到正确 ID；检查公开列表、项目详情和后续动态。
   验证符合条件的候选无需点击后台保存即可自动公开，证据不足的候选继续保留；新增公开报道后会自动重评，手动暂停的项目不被重新公开。
4. 检查 worker 的真实计划任务记录、请求回执和额度变化；手工触发成功不能代替计划任务验收。
5. 确认桌面和手机入口可用，取消公开报道后相关证据消失，前台重复打开不增加 API 请求。

部署后可运行只读检查：`node modules/rootdata/scripts/smoke.ts https://你的站点域名`。它访问列表、项目详情并检查匿名访问后台被拒绝，不消耗 RootData credits。

RootData 若升级套餐，需要另行实现并验证对应接口；仅更换 key 不会自动开放融资轮次或榜单抓取。
